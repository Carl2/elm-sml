#+AUTHOR: Carl Olsen
#+DATE: 2026-06-04

* Feature Overview

Add an optional context type that gets injected into guard and action lambdas.
The user provides a type name (e.g. =MyContext=); the generated C++ code
adds a =ContextType& ctx= parameter to lambdas and passes a context instance
to =sml::sm<>=.

* Goals

- Allow specifying a context type name for the generated state machine
- Generate guards/actions with context parameter
- Generate =main()= that constructs and injects the context
- Keep it simple: user just provides the type name, writes the struct themselves

* Non-goals

- Generating the context struct definition
- Per-machine context (one global context for all machines)
- Context member access helpers or code generation

* Constraints and Assumptions

- Context is global across all machines
- Guard lambda signature: =[](const auto& event, ContextType& ctx) { return true; }=
- Action lambda signature: =[](const auto& event, ContextType& ctx) {}=
- =makeMain= passes context: =ContextType ctx{}; sml::sm<Machine> sm{ctx};=
- If no context specified, existing signatures remain unchanged

* Risks and Open Questions

- Should the context parameter be =const&= for guards? (Boost.SML convention)
- Forward declaration or include needed for context type in generated header?

- New formatting functions that accept =Maybe String= context type
- =makeEventHeader= passes context type through

- =makeMain= conditionally generates context construction and injection
